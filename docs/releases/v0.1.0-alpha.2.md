The first OpenMixer release with installers for Linux, Windows and macOS. They open the new web interface (ADR 0009), built with Tauri, on the real audio engine.

This is an alpha: expect rough edges, and do not rely on it for a gig.

## Downloads

| System | File |
|---|---|
| Linux (Debian, Ubuntu) | `OpenMixer_0.1.0-alpha.2_amd64.deb` |
| Linux (Fedora, openSUSE) | `OpenMixer-0.1.0-0.alpha.2.x86_64.rpm` |
| Linux (any, glibc 2.35 or newer) | `OpenMixer_0.1.0-alpha.2_amd64.AppImage` |
| Windows 10 and 11 | `OpenMixer_0.1.0-alpha.2_x64-setup.exe` or the `.msi` |
| macOS 11 or newer, Apple silicon | `OpenMixer_0.1.0-alpha.2_aarch64.dmg` |

**First start on Windows:** if SmartScreen says "Windows protected your PC", choose **More info**, then **Run anyway**.

**First start on macOS:** the app is not notarised yet. Open it once, then go to System Settings, Privacy & Security, and choose **Open Anyway**.

## What is new since alpha.1

- **Installers** for Linux, Windows and macOS, built by a public workflow, with checksums and GitHub build provenance for every file.
- **Load tracks** in the web interface: the Load button on each deck opens a file dialog, and a file dropped on a deck loads there. A new file is added to your library and analysed like any other track.
- **Web interface** (ADR 0009): the decks screen (waveforms, deck headers, transport, hot cues, loops, mixer and meters) in a Tauri window. It opens your audio output as the GPUI window does.
- **Machined Faceplate** look (ADR 0008) with three themes and two densities.
- **CLAP plugin hosting** (ADR 0007), with plugin state kept across sessions.
- **EBU R128 loudness metering** of the master output.
- **MIDI on every platform** through midir.
- **Real-time priority** for the audio callback thread.
- **Beat grids** no longer lock half a beat late on off-beat-heavy tracks.

## Known limits

- The web interface has no settings page yet: the audio output is the one saved by the GPUI window, or the system default.
- Stems and Automix have not had a listening check; treat them as unverified.
- The Windows and macOS builds have only been run in CI, not tested by hand beyond a first start.
- No MIDI controller or plugin support in the web interface yet.

## Checking a download

```bash
sha256sum -c SHA256SUMS-linux.txt          # macOS: shasum -a 256 -c SHA256SUMS-macos.txt
gh attestation verify <file> --repo massive-development/openmixer
```

When a `.asc` file is attached, `gpg --verify SHA256SUMS-<os>.txt.asc` checks the checksums against the project key.
